23 Clase 20 — Asignación de Memoria No Contigua

23.1 De dónde venimos

En la clase anterior estudiamos la asignación de memoria contigua.

Encontramos una limitación importante:

Un proceso puede tener suficiente memoria libre disponible y, aun así, no poder cargarse si no existe un único hueco contiguo suficientemente grande.

Por ejemplo:

Huecos libres:
[90 KB, 70 KB, 60 KB, 80 KB]

Memoria libre total = 300 KB
Proceso P           = 150 KB
Mayor hueco         = 90 KB

Aunque existen 300 KB libres:

P → NO puede asignarse de forma contigua

La pregunta con la que cerramos fue:

¿Qué cambiaría si pudiéramos dividir un proceso y colocar sus partes en diferentes regiones de memoria física?

Ese es nuestro punto de partida.

24 Objetivos de aprendizaje

Al finalizar la clase, el estudiante podrá:

  1. explicar qué significa asignar memoria de forma no contigua;
  2. diferenciar una página de un marco;
  3. explicar el funcionamiento básico de la paginación;
  4. interpretar una tabla de páginas;
  5. traducir una dirección lógica sencilla a una dirección física;
  6. identificar ventajas y costos de la paginación;
  7. comparar asignación contigua y no contigua;
  8. representar gráficamente la ubicación de un proceso paginado.

25 1. Rompiendo una restricción

En asignación contigua teníamos:

Proceso P = 12 KB

y necesitábamos:

┌──────────────────────────┐
│ P = 12 KB continuos      │
└──────────────────────────┘

Pero imaginemos que la memoria física disponible se encuentra así:

┌──────────────┐
│ Ocupado      │
├──────────────┤
│ Libre 4 KB   │
├──────────────┤
│ Ocupado      │
├──────────────┤
│ Libre 4 KB   │
├──────────────┤
│ Ocupado      │
├──────────────┤
│ Libre 4 KB   │
└──────────────┘

Tenemos exactamente:

4 + 4 + 4 = 12 KB

Pero no existe un hueco continuo de 12 KB.

¿Y si pudiéramos hacer esto?

Proceso P
┌──────────┐
│ Parte 0  │ ──────────► Libre 4 KB
├──────────┤
│ Parte 1  │ ──────────► Libre 4 KB
├──────────┤
│ Parte 2  │ ──────────► Libre 4 KB
└──────────┘

Ahora sí podemos utilizar los tres espacios.

NotaIdea central

En la asignación no contigua, un proceso puede estar dividido en partes que se almacenan en diferentes regiones de la memoria física.

26 2. Paginación

Una de las técnicas fundamentales de asignación no contigua es la paginación.

La idea consiste en dividir:

  • el espacio de memoria del proceso en bloques de tamaño fijo llamados páginas;
  • la memoria física en bloques del mismo tamaño llamados marcos.
PROCESO                     MEMORIA FÍSICA

┌──────────┐                ┌──────────┐
│ Página 0 │                │ Marco 0  │
├──────────┤                ├──────────┤
│ Página 1 │                │ Marco 1  │
├──────────┤                ├──────────┤
│ Página 2 │                │ Marco 2  │
├──────────┤                ├──────────┤
│ Página 3 │                │ Marco 3  │
└──────────┘                ├──────────┤
                            │ Marco 4  │
                            ├──────────┤
                            │ Marco 5  │
                            └──────────┘

27 3. Página y marco no son lo mismo

ImportanteNo confundir

Página: bloque del espacio lógico del proceso.

Marco: bloque de la memoria física.

Si el tamaño de página es:

4 KB

entonces cada marco también mide:

4 KB

Esto permite colocar cualquier página en cualquier marco libre.

28 4. Un proceso ya no necesita estar junto

Supongamos:

Proceso P = 16 KB
Tamaño de página = 4 KB

Entonces:

Número de páginas = 16 / 4 = 4

El proceso se divide así:

P0 = Página 0
P1 = Página 1
P2 = Página 2
P3 = Página 3

Podrían ubicarse físicamente así:

MEMORIA FÍSICA

Marco 0   → Otro proceso
Marco 1   → Página 2 de P
Marco 2   → Libre
Marco 3   → Página 0 de P
Marco 4   → Otro proceso
Marco 5   → Página 3 de P
Marco 6   → Página 1 de P
Marco 7   → Libre

Observe algo importante:

Página 0 → Marco 3
Página 1 → Marco 6
Página 2 → Marco 1
Página 3 → Marco 5

Las páginas no necesitan estar en orden físico.

29 5. Entonces aparece un nuevo problema

El programa trabaja con su propio espacio lógico.

Por ejemplo, puede solicitar información que se encuentra en:

Página 2

Pero físicamente esa página está en:

Marco 1

¿Cómo sabe el sistema dónde encontrarla?

Necesitamos una estructura que mantenga esa correspondencia.

30 6. Tabla de páginas

La tabla de páginas relaciona cada página lógica con el marco físico donde se encuentra.

Para nuestro ejemplo:

Página Marco
0 3
1 6
2 1
3 5

Podemos leerla así:

Página 0 → Marco 3
Página 1 → Marco 6
Página 2 → Marco 1
Página 3 → Marco 5
TipLa tabla es el mapa

El proceso conoce sus páginas.

La memoria física contiene marcos.

La tabla de páginas permite relacionar ambos mundos.

31 7. Dirección lógica

Una dirección generada por el proceso puede separarse conceptualmente en:

┌──────────────┬────────────────┐
│   Página     │ Desplazamiento │
└──────────────┴────────────────┘

La página indica qué bloque lógico contiene el dato.

El desplazamiento indica la posición del dato dentro de esa página.

Por ejemplo:

Página = 2
Desplazamiento = 500 bytes

Significa:

El dato se encuentra 500 bytes después del inicio de la página 2.

32 8. Traducción de dirección

Supongamos:

Página lógica = 2
Desplazamiento = 500 bytes

La tabla indica:

Página 2 → Marco 1

Por lo tanto:

Dirección lógica:
[ Página 2 | desplazamiento 500 ]

                  ↓ tabla de páginas

Dirección física:
[ Marco 1  | desplazamiento 500 ]

Observe:

El desplazamiento no cambia.

Lo que cambia es la página lógica por el marco físico correspondiente.

33 9. Dirección física numérica

Ahora podemos calcular la dirección física.

Si:

Tamaño de marco = 4096 bytes
Marco = 1
Desplazamiento = 500 bytes

Entonces:

Dirección física
= (marco × tamaño del marco) + desplazamiento

= (1 × 4096) + 500

= 4596

Por tanto:

Dirección física = 4596

34 10. Ejemplo completo

Tenemos:

Tamaño de página = 1 KB = 1024 bytes

Tabla:

Página Marco
0 5
1 2
2 7
3 1

El proceso genera:

Página = 2
Desplazamiento = 300

34.0.1 Paso 1 — Consultar la tabla

Página 2 → Marco 7

34.0.2 Paso 2 — Mantener el desplazamiento

Desplazamiento = 300

34.0.3 Paso 3 — Calcular

Dirección física
= (7 × 1024) + 300
= 7168 + 300
= 7468

Resultado:

Dirección física = 7468

35 11. ¿Y si nos dan una dirección lógica completa?

Supongamos:

Tamaño de página = 1000 bytes
Dirección lógica = 2350

Tenemos que descubrir:

¿En qué página está?
¿A qué distancia del inicio de esa página?

Calculamos:

Página = dirección lógica / tamaño de página

Página = 2350 / 1000
Página = 2

Usamos la parte entera.

El desplazamiento es:

Desplazamiento = 2350 % 1000
Desplazamiento = 350

Entonces:

2350 → Página 2 + desplazamiento 350
NotaRegla práctica

Para una dirección lógica:

página = dirección / tamaño_página
desplazamiento = dirección % tamaño_página

Se utiliza división entera para obtener la página.

36 12. Hagamos la traducción completa

Tabla:

Página Marco
0 4
1 7
2 1
3 5

Datos:

Tamaño de página = 1000 bytes
Dirección lógica = 2350

Ya sabemos:

Página = 2
Desplazamiento = 350

Consultamos:

Página 2 → Marco 1

Finalmente:

Dirección física
= (1 × 1000) + 350
= 1350

Por tanto:

Dirección lógica 2350
          ↓
Página 2 | desplazamiento 350
          ↓
Tabla de páginas
          ↓
Marco 1  | desplazamiento 350
          ↓
Dirección física 1350

37 13. ¿Quién realiza esta traducción?

En los sistemas modernos, la traducción de direcciones se apoya en hardware especializado.

Ya conocimos este componente:

MMU — Memory Management Unit

Conceptualmente:

CPU

 │ Dirección lógica
 ▼
┌──────────────┐
│     MMU      │
└──────────────┘
 │
 │ Traducción
 ▼
Tabla de páginas
 │
 ▼
Dirección física
 │
 ▼
Memoria RAM
NotaConexión con clases anteriores

En multiprogramación vimos que la MMU participa en la traducción de direcciones lógicas a físicas durante la ejecución.

Ahora podemos comprender cómo una tabla de páginas forma parte de ese proceso de traducción.

38 14. Una ventaja importante

Regresemos al problema inicial:

Huecos:
[4 KB, 4 KB, 4 KB]

Proceso:
12 KB

Con asignación contigua:

NO cabe.

Con páginas de 4 KB:

Proceso = 3 páginas

Podemos utilizar tres marcos libres separados:

Página 0 → Marco libre A
Página 1 → Marco libre F
Página 2 → Marco libre C

Por lo tanto:

SÍ puede asignarse.

Esta es una de las grandes ventajas de la asignación no contigua.

39 15. ¿Desaparece la fragmentación?

Una conclusión apresurada sería:

“Si utilizamos paginación ya no existe fragmentación.”

Eso sería incorrecto.

La paginación evita el problema clásico de fragmentación externa asociado con la necesidad de grandes huecos contiguos.

Pero todavía puede existir fragmentación interna.

40 16. Fragmentación interna en paginación

Supongamos:

Tamaño de página = 4 KB
Proceso = 10 KB

Necesitamos:

Página 0 = 4 KB
Página 1 = 4 KB
Página 2 = 2 KB utilizados

Pero la última página ocupa un marco completo de 4 KB.

Último marco:

┌─────────────────┐
│ Usado      2 KB │
├─────────────────┤
│ Sin usar   2 KB │
└─────────────────┘

Entonces:

Fragmentación interna = 2 KB
ImportanteConclusión

La paginación reduce el problema de la fragmentación externa, pero puede producir fragmentación interna, especialmente en la última página de un proceso.

41 17. ¿Cuántas páginas necesita un proceso?

Supongamos:

Proceso = 18 KB
Página = 4 KB

Dividimos:

18 / 4 = 4.5

No podemos utilizar media página física.

Necesitamos:

5 páginas

Capacidad reservada:

5 × 4 = 20 KB

Espacio no utilizado:

20 - 18 = 2 KB

45 21. Lo que ganamos y lo que cuesta

45.1 Ventajas

  • Un proceso no necesita ocupar un único bloque contiguo.
  • Se aprovechan marcos libres distribuidos en memoria.
  • Se reduce el problema de fragmentación externa.
  • Facilita una administración más flexible de la memoria.

45.2 Costos

  • Debemos mantener tablas de páginas.
  • Cada acceso requiere traducir una dirección lógica a física.
  • Las estructuras de traducción también consumen memoria.
  • Puede existir fragmentación interna.
  • La administración es más compleja que en un modelo contiguo.

46 22. Contigua vs. No Contigua

Característica Contigua No contigua / paginación
Ubicación del proceso Un bloque continuo Varios marcos
División del proceso No necesaria Páginas
Unidad física Bloque/partición Marco
Fragmentación externa Puede ocurrir Se reduce significativamente
Fragmentación interna Puede ocurrir Puede ocurrir
Traducción Más sencilla Requiere correspondencia página-marco
Estructura adicional Menor Tabla de páginas
Flexibilidad Menor Mayor

47 23. Un caso para pensar como ingeniero

Un sistema tiene marcos libres:

Marco 1
Marco 4
Marco 7
Marco 9

Cada marco mide:

4 KB

Llega un proceso:

P = 14 KB

Preguntas:

  1. ¿Cuántas páginas necesita?
  2. ¿Puede cargarse utilizando esos cuatro marcos?
  3. Proponga una tabla de páginas.
  4. ¿Cuánta fragmentación interna queda?
  5. Dibuje el resultado.

Una solución posible:

P necesita 4 páginas.

Página 0 → Marco 1
Página 1 → Marco 4
Página 2 → Marco 7
Página 3 → Marco 9

Memoria reservada:

4 × 4 = 16 KB

Fragmentación interna:

16 - 14 = 2 KB

48 24. ¿Qué sucedería si…?

Analice cada situación.

48.0.1 Situación A

Hay suficiente memoria libre total, pero ningún hueco contiguo es suficientemente grande.

¿Qué modelo tiene ventaja?

La asignación no contigua.

48.0.2 Situación B

Una página lógica cambia de marco físico.

¿Debe cambiar la dirección lógica utilizada por el proceso?

Conceptualmente, no. La correspondencia de la tabla permite mantener separado el espacio lógico de la ubicación física.

48.0.3 Situación C

Un proceso utiliza solamente una pequeña parte de su última página.

¿Qué tipo de desperdicio aparece?

Fragmentación interna.

51 27. De la asignación al diseño

Hasta este punto hemos visto dos formas diferentes de enfrentar el mismo problema:

¿Cómo colocar procesos en memoria?

51.0.1 Asignación contigua

Buscar un bloque suficientemente grande.

51.0.2 Asignación no contigua

Dividir el proceso y utilizar diferentes marcos.

Pero esto introduce nuevas preguntas:

  • ¿Cómo administrar tablas de páginas grandes?
  • ¿Qué sucede si una página necesaria no está actualmente en RAM?

  • ¿Qué relación existe entre paginación y memoria virtual?

Estas preguntas abren el siguiente nivel de la administración de memoria.

Ese cambio permite que un proceso ya no dependa de un único espacio físico contiguo.

53.1 Respuestas del cierre

  1. Permite almacenar las diferentes partes de un proceso en regiones físicas separadas.
  2. Una página pertenece al espacio lógico del proceso; un marco pertenece a la memoria física.
  3. Mantiene la correspondencia entre páginas lógicas y marcos físicos.
  4. Número de página y desplazamiento.
  5. El desplazamiento.
  6. Participa en la traducción de direcciones lógicas a físicas durante la ejecución.
  7. Porque no exige un único hueco físico continuo para almacenar todo el proceso.
  8. Porque la última página puede no utilizar completamente el marco que tiene asignado.
  9. Puede aprovechar marcos libres dispersos en la memoria.
  10. Tablas de páginas, traducción de direcciones, consumo adicional de memoria y mayor complejidad de administración.

53.2 Respuestas de la actividad corta

Con páginas de 1 KB = 1024 bytes:

53.2.1 A = 450

Página 0
Desplazamiento 450
Página 0 → Marco 3
Física = (3 × 1024) + 450 = 3522

53.2.2 B = 1750

Página 1
Desplazamiento = 1750 - 1024 = 726
Página 1 → Marco 8
Física = (8 × 1024) + 726 = 8918

53.2.3 C = 3200

Página 3
Desplazamiento = 3200 - 3072 = 128
Página 3 → Marco 6
Física = (6 × 1024) + 128 = 6272

53.2.4 D = 4090

Página 3
Desplazamiento = 4090 - 3072 = 1018
Página 3 → Marco 6
Física = (6 × 1024) + 1018 = 7162
