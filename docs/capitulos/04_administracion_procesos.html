6 Presentación

Cada vez que abrimos un navegador, reproducimos música o editamos un documento, el Sistema Operativo crea y administra procesos. Aunque parezca que todas las aplicaciones trabajan al mismo tiempo, en realidad el procesador distribuye su tiempo entre ellas de forma extremadamente rápida.

TipObjetivos
  • Comprender qué es un proceso.
  • Diferenciar programa y proceso.
  • Explicar el modelo de procesos.
  • Comprender los estados de un proceso.
  • Interpretar el funcionamiento del PCB.

7 ¿Qué es un proceso?

Un proceso es un programa que se encuentra en ejecución junto con todos los recursos que necesita para funcionar: memoria, registros, archivos abiertos y tiempo de CPU.

Programa Proceso
Archivo almacenado Programa en ejecución
Pasivo Dinámico
No consume recursos Consume CPU, memoria y E/S

7.1 Analogía

Una receta de cocina representa un programa. Preparar la receta utilizando ingredientes, tiempo y utensilios representa el proceso.

8 Modelo de Procesos

El Sistema Operativo crea la ilusión de que cada aplicación posee su propio procesador. En realidad, el Scheduler distribuye pequeños intervalos de tiempo entre todos los procesos.

NotaIdea clave

La multitarea es posible porque el Sistema Operativo cambia rápidamente entre procesos mediante el Cambio de Contexto (Context Switch).

9 Programa vs. Proceso

Un único programa puede generar múltiples procesos independientes.

10 Espacio de Direcciones

Cada proceso dispone de un espacio de memoria independiente.

11 Bloque de Control del Proceso (PCB)

El PCB es el expediente administrativo del proceso.

Campo Descripción
PID Identificador único
Estado Estado actual
Program Counter Próxima instrucción
Registros Contexto de CPU
Memoria Espacio asignado
Archivos Recursos abiertos

12 Tabla de Procesos

El kernel mantiene una tabla donde registra todos los PCB existentes.

TipEstructura simplificada de una Tabla de Procesos

La tabla de procesos es una estructura interna mantenida por el Kernel, donde se almacena el PCB (Process Control Block) de todos los procesos existentes en el sistema. Cada entrada contiene la información necesaria para que el sistema operativo pueda administrar correctamente cada proceso.

12.0.1 Ejemplo de una Tabla de Procesos

PID Nombre del proceso Estado Prioridad Memoria (MB) CPU (%) Archivos abiertos
1001 Chrome.exe Running Alta 245 18 27
1002 Word.exe Ready Media 132 0 12
1003 Spotify.exe Waiting Baja 95 0 8
1004 Teams.exe Ready Alta 318 0 34
1005 Explorer.exe Running Alta 76 5 19

Interpretación

  • PID: Identificador único asignado por el sistema operativo.
  • Nombre del proceso: Aplicación o servicio que se encuentra en ejecución.
  • Estado: Situación actual del proceso (Running, Ready o Waiting).
  • Prioridad: Nivel de importancia utilizado por el Scheduler.
  • Memoria: Cantidad de memoria RAM reservada por el proceso.
  • CPU: Porcentaje de utilización del procesador en ese instante.
  • Archivos abiertos: Número de archivos o recursos que el proceso mantiene abiertos.

13 Módelos de Estados de un Proceso

13.1 Evolución de los modelos de estados

Modelo Estados ¿Dónde se utiliza?
Dos estados Listo y Ejecución Sistemas muy simples o con fines didácticos.
Cinco estados Nuevo, Listo, Ejecución, Bloqueado y Terminado Es el modelo más utilizado para explicar la administración de procesos.
Siete estados Cinco estados + Listo Suspendido + Bloqueado Suspendido Sistemas operativos modernos que utilizan memoria virtual y Swap.

13.2 Modelo de cinco estados

El modelo de cinco estados es uno de los más utilizados para explicar el ciclo de vida de un proceso en un sistema operativo. En este modelo, un proceso puede encontrarse en uno de cinco estados bien definidos, y el sistema operativo controla las transiciones entre ellos.

13.2.1 Descripción de los estados

Estado Descripción
Nuevo El proceso acaba de ser creado y aún no está listo para ejecutarse.
Listo (Ready) El proceso posee todos los recursos necesarios excepto la CPU. Espera su turno para ejecutarse.
Ejecución (Running) El proceso está utilizando el procesador y ejecutando instrucciones.
Bloqueado (Waiting) El proceso espera la finalización de una operación de entrada/salida o algún evento externo.
Terminado (Exit) El proceso concluyó su ejecución y el sistema operativo libera los recursos utilizados.
TipIdea clave

Todo proceso pasa necesariamente por los estados Nuevo y Terminado, mientras que los estados Listo, Ejecución y Bloqueado pueden repetirse varias veces durante su ciclo de vida.

13.3 Modelo con procesos suspendidos (Swap)

En sistemas multitarea es posible que la memoria principal no sea suficiente para mantener todos los procesos cargados simultáneamente. En estos casos, el sistema operativo puede mover temporalmente algunos procesos al almacenamiento secundario mediante una técnica denominada Swap o Intercambio de memoria.

Cuando esto ocurre aparecen dos nuevos estados:

  • Listo y Suspendido
  • Bloqueado y Suspendido

13.3.1 Nuevos estados

Estado Descripción
Listo y Suspendido El proceso está preparado para ejecutarse, pero fue trasladado al disco porque no existe memoria RAM suficiente.
Bloqueado y Suspendido El proceso permanece esperando un evento y, además, fue movido temporalmente al almacenamiento secundario.
Nota¿Qué es el Swap?

El Swap consiste en mover procesos completos o parte de su memoria desde la RAM hacia un área especial del disco duro o del SSD para liberar memoria física y permitir que otros procesos continúen ejecutándose.

Aunque esta técnica incrementa la capacidad de ejecución del sistema, también reduce el rendimiento, ya que acceder al disco es mucho más lento que acceder a la memoria RAM.

14 Resumen

  • Un programa se convierte en proceso al ejecutarse.
  • Cada proceso posee memoria y recursos propios.
  • El PCB almacena toda la información necesaria para administrarlo.
  • El Scheduler comparte el procesador entre todos los procesos.
  • En la siguiente sección estudiaremos el ciclo de vida y los estados de un proceso.

15 Scheduler y Dispatcher

El Scheduler decide qué proceso obtendrá el procesador cuando existen varios procesos listos para ejecutarse. Para tomar esta decisión puede considerar la prioridad, el tiempo de espera o el algoritmo de planificación configurado por el sistema operativo.

El Dispatcher es el componente encargado de entregar realmente la CPU al proceso seleccionado y realizar el cambio de contexto.

16 Cambio de contexto (Context Switch)

Un cambio de contexto ocurre cuando el sistema operativo detiene temporalmente un proceso, guarda su estado en el PCB y restaura el estado de otro proceso.

17 Ejemplo completo: Microsoft Word

  1. El usuario hace doble clic sobre Word.exe.
  2. El Kernel crea el proceso y asigna un PID.
  3. El proceso entra al estado NEW.
  4. Se reserva memoria y se crea el PCB.
  5. El proceso pasa a READY.
  6. El Scheduler selecciona el proceso.
  7. El Dispatcher entrega la CPU.
  8. El proceso entra en RUNNING.
  9. Al guardar un archivo, espera la respuesta del disco (WAITING).
  10. Finalizada la operación de E/S vuelve a READY.
  11. El Scheduler le asigna nuevamente la CPU.
  12. Al cerrar Word, el proceso entra en EXIT y el sistema libera memoria, archivos y demás recursos.
