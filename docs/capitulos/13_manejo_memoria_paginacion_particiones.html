14  Capítulo 13. Manejo de memoria: particiones y paginación

15 Capítulo 13. Manejo de memoria: particiones y paginación

15.1 ¿Cómo caben tantos programas en la memoria?

En una computadora podemos tener abierto el navegador, un editor de código, música, una videollamada y otros programas al mismo tiempo.

Todos necesitan memoria RAM.

Pero la RAM es limitada.

Entonces aparece una pregunta fundamental:

¿Cómo decide el Sistema Operativo qué parte de la memoria utiliza cada proceso?

La respuesta nos lleva a uno de los trabajos más importantes del Sistema Operativo: la gestión de memoria.

TipIdea central

El Sistema Operativo debe asignar, proteger, controlar y liberar memoria para que varios procesos puedan ejecutarse sin interferirse entre sí.

16 Objetivos de aprendizaje

Al finalizar este capítulo, el estudiante será capaz de:

  • Explicar por qué la gestión de memoria es una función crítica del Sistema Operativo.
  • Diferenciar una dirección lógica de una dirección física.
  • Comprender el funcionamiento de las particiones fijas y dinámicas.
  • Diferenciar fragmentación interna y fragmentación externa.
  • Aplicar conceptualmente los métodos First Fit, Best Fit y Worst Fit.
  • Explicar los conceptos de página, marco y tabla de páginas.
  • Comprender cómo se traduce una dirección lógica en una dirección física.
  • Explicar por qué la paginación permite utilizar memoria no contigua.
  • Relacionar paginación con memoria virtual.
  • Comparar particiones y paginación mediante situaciones prácticas.

17 1. La memoria RAM como recurso crítico

La memoria RAM almacena temporalmente instrucciones y datos que necesitan los procesos mientras se ejecutan.

Cuando un programa comienza a ejecutarse, no basta con tenerlo almacenado en el disco. Parte de su contenido debe encontrarse disponible en memoria.

El Sistema Operativo debe decidir:

  1. qué proceso recibe memoria;
  2. cuánta memoria recibe;
  3. dónde se coloca;
  4. cómo se protege de otros procesos;
  5. cuándo se libera.
NotaUna analogía: el estacionamiento

Imaginemos que la RAM es un estacionamiento y los procesos son vehículos.

El Sistema Operativo funciona como el encargado que decide dónde estacionar cada vehículo, evita que dos ocupen el mismo espacio y libera el lugar cuando un vehículo se retira.

17.1 ¿Por qué importa?

Una mala administración de memoria puede provocar:

  • desperdicio de espacio;
  • dificultad para cargar nuevos procesos;
  • bajo rendimiento;
  • errores de acceso;
  • imposibilidad de aprovechar correctamente la memoria disponible.

18 2. Dirección lógica y dirección física

Cuando un programa utiliza memoria, normalmente no trabaja directamente con la posición física real de la RAM.

Debemos distinguir dos conceptos.

Dirección Significado
Lógica Dirección que utiliza o genera el programa
Física Ubicación real correspondiente dentro de la memoria RAM

ImportanteNo debemos confundirlas

El proceso puede pensar en una dirección dentro de su propio espacio de memoria, mientras el hardware y el Sistema Operativo determinan dónde se encuentra realmente esa información en la RAM.

19 3. Primera estrategia: dividir la memoria en particiones

Una forma sencilla de administrar memoria consiste en dividirla en bloques o particiones.

Cada proceso ocupa una partición.

Existen dos enfoques principales:

PARTICIONES
   │
   ├── Fijas
   │
   └── Dinámicas

La diferencia parece pequeña, pero produce problemas de fragmentación diferentes.

20 4. Particiones fijas

En las particiones fijas, la memoria se divide previamente en bloques de tamaño definido.

Supongamos una memoria disponible de 8 MB, dividida en cuatro particiones de 2 MB:

RAM
┌──────────────────┐
│ Partición 1: 2MB │
├──────────────────┤
│ Partición 2: 2MB │
├──────────────────┤
│ Partición 3: 2MB │
├──────────────────┤
│ Partición 4: 2MB │
└──────────────────┘

Ahora llegan tres procesos:

Proceso A = 1.2 MB
Proceso B = 1.8 MB
Proceso C = 0.9 MB

Podemos asignar uno a cada partición.

Pero observemos lo que ocurre:

Partición Tamaño Proceso Utilizado Desperdiciado
1 2 MB A 1.2 MB 0.8 MB
2 2 MB B 1.8 MB 0.2 MB
3 2 MB C 0.9 MB 1.1 MB
4 2 MB Libre — —

Los espacios que sobran dentro de una partición ocupada no pueden ser aprovechados fácilmente por otro proceso.

Eso se llama fragmentación interna.

AdvertenciaFragmentación interna

Existe memoria asignada a un proceso que realmente no está siendo utilizada, pero permanece encerrada dentro del bloque asignado.

20.1 Ventaja principal

  • Es un esquema sencillo de administrar.

20.2 Problema principal

  • Puede desperdiciar bastante memoria debido a la fragmentación interna.

21 5. Particiones dinámicas

¿Y si en lugar de construir bloques rígidos permitimos que cada proceso reciba aproximadamente el espacio que necesita?

Ese es el principio de las particiones dinámicas.

Supongamos:

RAM disponible = 16 MB

Proceso A = 4 MB
Proceso B = 6 MB
Proceso C = 2 MB

La memoria podría verse así:

┌──────────────────┐
│ Proceso A   4 MB │
├──────────────────┤
│ Proceso B   6 MB │
├──────────────────┤
│ Proceso C   2 MB │
├──────────────────┤
│ Libre       4 MB │
└──────────────────┘

Hasta aquí parece una solución excelente.

Pero los procesos terminan.

Imaginemos que Proceso B finaliza:

┌──────────────────┐
│ Proceso A   4 MB │
├──────────────────┤
│ LIBRE       6 MB │
├──────────────────┤
│ Proceso C   2 MB │
├──────────────────┤
│ LIBRE       4 MB │
└──────────────────┘

Ahora tenemos 10 MB libres, pero están separados en dos huecos.

Esto introduce otro problema.

22 6. Fragmentación interna y externa

Estos conceptos suelen confundirse.

22.1 Fragmentación interna

El desperdicio se encuentra dentro del espacio asignado.

Partición de 4 KB
┌────────────────────┐
│ Proceso: 3 KB      │
│                    │
│ Desperdicio: 1 KB  │ ← dentro
└────────────────────┘

22.2 Fragmentación externa

Existe suficiente memoria libre en total, pero se encuentra dispersa entre espacios ocupados.

┌──────────────┐
│ Proceso A    │
├──────────────┤
│ Libre 2 MB   │
├──────────────┤
│ Proceso B    │
├──────────────┤
│ Libre 3 MB   │
├──────────────┤
│ Proceso C    │
├──────────────┤
│ Libre 1 MB   │
└──────────────┘

Tenemos:

2 + 3 + 1 = 6 MB libres

pero no existe necesariamente un bloque contiguo de 6 MB.

Tipo ¿Dónde está el desperdicio? Ejemplo típico
Interna Dentro del bloque asignado Particiones fijas / último marco de una página
Externa Entre bloques ocupados Particiones dinámicas
TipTruco para recordarlo

Interna → adentro del bloque.
Externa → afuera, entre los bloques.

23 7. ¿Qué hueco debemos utilizar?

Con particiones dinámicas aparece otra pregunta:

Si existen varios espacios libres, ¿en cuál colocamos el nuevo proceso?

Tres estrategias clásicas son:

  • First Fit
  • Best Fit
  • Worst Fit

Supongamos que tenemos estos huecos:

10 KB   4 KB   20 KB   7 KB

y llega un proceso de:

6 KB

24 8. First Fit: el primer espacio suficiente

First Fit recorre la memoria y selecciona el primer hueco que sea suficientemente grande.

Para nuestro proceso de 6 KB:

Huecos: 10 KB | 4 KB | 20 KB | 7 KB
          ↑
       elegido

El primer hueco de 10 KB puede alojarlo.

Quedan:

10 - 6 = 4 KB
NotaIdea de First Fit

No busca el hueco perfecto. Busca el primero que funcione.

25 9. Best Fit: el espacio más ajustado

Best Fit busca el hueco disponible más pequeño que todavía pueda alojar el proceso.

Huecos: 10 KB | 4 KB | 20 KB | 7 KB
                                  ↑
                               elegido

Para un proceso de 6 KB, el hueco de 7 KB es el más ajustado.

Queda:

7 - 6 = 1 KB

La idea parece eficiente porque deja poco sobrante en esa asignación, aunque puede producir huecos pequeños difíciles de reutilizar.

26 10. Worst Fit: el espacio más grande

Worst Fit hace lo contrario: selecciona el hueco más grande.

Huecos: 10 KB | 4 KB | 20 KB | 7 KB
                         ↑
                      elegido

El proceso de 6 KB entra en el hueco de 20 KB.

Quedan:

20 - 6 = 14 KB

La intención es conservar un espacio sobrante suficientemente grande para ser útil posteriormente.

27 11. Comparando los tres métodos

Para:

Huecos = 10, 4, 20, 7 KB
Proceso = 6 KB
Método Hueco elegido Espacio restante
First Fit 10 KB 4 KB
Best Fit 7 KB 1 KB
Worst Fit 20 KB 14 KB
ImportanteNo existe magia

Estos algoritmos toman decisiones distintas sobre el mismo estado de memoria. La elección puede influir en cómo quedan distribuidos los huecos para futuras solicitudes.

27.1 Actividad rápida

Tenemos:

Huecos libres: 5 KB, 12 KB, 8 KB, 20 KB
Proceso nuevo: 7 KB

Determina qué hueco seleccionaría:

  1. First Fit.
  2. Best Fit.
  3. Worst Fit.
Tip✅ Solución propuesta
  • First Fit: 12 KB, porque es el primer hueco suficientemente grande.
  • Best Fit: 8 KB, porque es el hueco válido más pequeño.
  • Worst Fit: 20 KB, porque es el hueco más grande.

Después de colocar un proceso de 7 KB quedarían, respectivamente:

  • First Fit → 5 KB libres en ese hueco.
  • Best Fit → 1 KB libre.
  • Worst Fit → 13 KB libres.

28 12. El problema de exigir memoria contigua

Las particiones tienen una limitación importante: un proceso necesita tradicionalmente un bloque continuo de memoria.

Supongamos:

Libre total = 12 KB

pero distribuido así:

4 KB + 3 KB + 5 KB

Un proceso de 10 KB no cabe en ninguno de los huecos individualmente.

Entonces surge una idea poderosa:

¿Y si dividimos el proceso en pequeñas partes y permitimos colocarlas en distintos lugares de la RAM?

Esa idea nos lleva a la paginación.

29 13. Introducción a la paginación

La paginación divide:

  • el espacio lógico del proceso en páginas;
  • la memoria física en marcos.

Y ambos tienen el mismo tamaño.

PROCESO                     RAM
┌──────────┐               ┌──────────┐
│ Página 0 │               │ Marco 0  │
├──────────┤               ├──────────┤
│ Página 1 │               │ Marco 1  │
├──────────┤               ├──────────┤
│ Página 2 │               │ Marco 2  │
├──────────┤               ├──────────┤
│ Página 3 │               │ Marco 3  │
└──────────┘               ├──────────┤
                           │ Marco 4  │
                           └──────────┘
TipDos palabras fundamentales

Página = unidad lógica del proceso.
Marco = unidad física de la RAM.

30 14. La gran ventaja: memoria no contigua

Supongamos un proceso de 4 páginas.

No es necesario colocarlas juntas.

Podrían distribuirse así:

Página 0 → Marco 5
Página 1 → Marco 2
Página 2 → Marco 8
Página 3 → Marco 1

Visualmente:

PROCESO                    MEMORIA FÍSICA
P0 ─────────────────────→ M5
P1 ───────────────→       M2
P2 ─────────────────────→ M8
P3 ───────→               M1

Para el proceso, sus páginas forman parte de un mismo espacio lógico.

En la RAM, pueden encontrarse en lugares separados.

ImportanteAquí está el cambio de paradigma

Con paginación, un proceso ya no necesita ocupar un único bloque físico contiguo de memoria.

31 15. Ejemplo numérico de paginación

Tenemos un proceso de:

10 KB

y utilizamos páginas de:

1 KB

Entonces:

10 KB ÷ 1 KB = 10 páginas

El proceso tendrá:

P0, P1, P2, P3, P4, P5, P6, P7, P8, P9

La RAM también se divide en marcos de 1 KB.

Cada página puede colocarse en cualquier marco disponible.

El diagrama muestra solo algunas páginas para concentrarnos en el mecanismo.

32 16. ¿Cómo sabe el Sistema Operativo dónde está cada página?

Necesitamos una estructura que mantenga la relación entre:

Página lógica ↔ Marco físico

Esa estructura es la tabla de páginas.

Ejemplo:

Página Marco
0 5
1 2
2 8
3 1

Si el proceso solicita información de la Página 2, la tabla indica:

Página 2 → Marco 8
NotaLa tabla funciona como un mapa

El proceso trabaja con páginas. La tabla de páginas permite encontrar el marco físico donde se encuentra cada una.

33 17. Dirección lógica = página + desplazamiento

Una dirección lógica paginada puede pensarse como dos componentes:

┌────────────┬─────────────────┐
│   Página   │ Desplazamiento  │
└────────────┴─────────────────┘

La página indica qué página necesitamos.

El desplazamiento indica la posición dentro de esa página.

Supongamos:

Dirección lógica:
Página = 2
Desplazamiento = 100

La tabla contiene:

Página 2 → Marco 5

Entonces la dirección física será conceptualmente:

Marco = 5
Desplazamiento = 100

Observe algo importante:

El desplazamiento no cambia.

Lo que cambia mediante la tabla es la página lógica por su marco físico correspondiente.

34 18. Calculando una dirección física

Podemos llevar el concepto un paso más adelante.

Si cada página y marco mide 1 KB, entonces:

1 KB = 1024 bytes

Tenemos:

Página lógica = 2
Desplazamiento = 100
Página 2 → Marco 5

La dirección física numérica puede calcularse como:

Dirección física = (marco × tamaño del marco) + desplazamiento

Entonces:

Dirección física = (5 × 1024) + 100
                  = 5120 + 100
                  = 5220

Por lo tanto:

La dirección lógica (Página 2, desplazamiento 100) corresponde a la dirección física 5220.

AdvertenciaNo memorices sin comprender

La fórmula tiene sentido porque primero llegamos al inicio del Marco 5 y luego avanzamos 100 bytes dentro de él.

34.1 Practiquemos

Página de 1 KB. La tabla indica:

Página 3 → Marco 7

La dirección lógica es:

Página = 3
Desplazamiento = 200

¿Cuál es la dirección física?

Tip✅ Solución propuesta

Como:

1 KB = 1024 bytes

y:

Página 3 → Marco 7

calculamos:

Dirección física = (7 × 1024) + 200
                  = 7168 + 200
                  = 7368

La dirección física es 7368.

35 19. ¿La paginación elimina toda fragmentación?

No.

La paginación evita el problema clásico de fragmentación externa, porque las páginas pueden colocarse en marcos separados.

Sin embargo, todavía puede existir fragmentación interna, especialmente en el último marco utilizado por un proceso.

Ejemplo:

Proceso = 10 KB
Página  = 4 KB

Necesitamos:

Página 0 = 4 KB
Página 1 = 4 KB
Página 2 = 2 KB utilizados

Pero el último marco mide 4 KB.

Último marco:
┌──────────────────┐
│ 2 KB utilizados  │
├──────────────────┤
│ 2 KB sin utilizar│ ← fragmentación interna
└──────────────────┘

Por tanto:

Fragmentación interna = 2 KB
ImportanteUna precisión importante

La paginación resuelve la necesidad de encontrar un gran bloque contiguo, pero no significa que todo byte de cada marco asignado será aprovechado.

36 20. Ventajas y costos de la paginación

36.1 Ventajas

  • Evita la fragmentación externa clásica.
  • Permite memoria física no contigua.
  • Facilita una utilización más flexible de los marcos disponibles.
  • Es una base importante para implementar memoria virtual.

36.2 Costos o desventajas

  • Puede existir fragmentación interna.
  • Cada proceso necesita información de traducción.
  • Las tablas de páginas consumen memoria.
  • La traducción de direcciones agrega trabajo al sistema.
Particiones Paginación
Conceptualmente simples Más flexible
Pueden requerir bloques contiguos Permite marcos no contiguos
Dinámicas: fragmentación externa Evita fragmentación externa clásica
Fijas: fragmentación interna Puede presentar fragmentación interna
Menor complejidad conceptual Requiere tabla de páginas

37 21. De la paginación a la memoria virtual

Hasta ahora hemos supuesto que las páginas del proceso están en RAM.

Pero aparece una posibilidad aún más interesante:

¿Qué ocurre si un programa necesita más memoria de la que podemos mantener físicamente en RAM en ese momento?

La memoria virtual permite extender el espacio disponible utilizando almacenamiento secundario y mecanismos administrados por el Sistema Operativo.

En un sistema paginado, algunas páginas pueden estar en RAM mientras otras no se encuentran cargadas en ese instante.

NotaLa idea que debemos conservar

La memoria virtual permite que el espacio que observa un proceso no tenga que corresponder completamente, en todo momento, con la cantidad de RAM física que ocupa.

38 22. Caso práctico integrador

Tenemos una RAM disponible de 16 KB.

Llegan tres procesos:

Proceso X = 4 KB
Proceso Y = 6 KB
Proceso Z = 2 KB

38.1 Escenario A: particiones dinámicas

Inicialmente podrían almacenarse de forma contigua:

┌──────────────────┐
│ Proceso X   4 KB │
├──────────────────┤
│ Proceso Y   6 KB │
├──────────────────┤
│ Proceso Z   2 KB │
├──────────────────┤
│ Libre       4 KB │
└──────────────────┘

Si posteriormente termina el Proceso Y:

┌──────────────────┐
│ Proceso X   4 KB │
├──────────────────┤
│ Libre       6 KB │
├──────────────────┤
│ Proceso Z   2 KB │
├──────────────────┤
│ Libre       4 KB │
└──────────────────┘

Tenemos dos huecos separados.

38.2 Escenario B: paginación de 2 KB

La RAM de 16 KB contiene:

16 ÷ 2 = 8 marcos

Los procesos requieren:

X = 4 KB → 2 páginas
Y = 6 KB → 3 páginas
Z = 2 KB → 1 página

En total:

2 + 3 + 1 = 6 marcos utilizados

Las páginas podrían distribuirse, por ejemplo:

Página Marco
X0 0
Y0 1
Z0 2
X1 4
Y1 6
Y2 7

No necesitan estar juntas.

TipPregunta para discutir

Si quedan libres los marcos 3 y 5, ¿representa eso el mismo problema que dos huecos separados en particiones dinámicas?

No necesariamente. En paginación, un nuevo proceso puede utilizar marcos libres separados porque sus páginas tampoco necesitan quedar contiguas.

39 23. Laboratorio en clase: tú administras la RAM

Supongamos una memoria de 32 KB.

Existen estos huecos libres:

H1 = 8 KB
H2 = 5 KB
H3 = 12 KB
H4 = 7 KB

Llegan, en este orden:

Proceso A = 6 KB
Proceso B = 4 KB
Proceso C = 7 KB

39.1 Parte A — Particiones dinámicas

Realiza la asignación utilizando por separado:

  1. First Fit.
  2. Best Fit.
  3. Worst Fit.

Después de cada proceso, anota cómo quedan los huecos.

39.2 Parte B — Paginación

Ahora supongamos páginas y marcos de 2 KB.

Determina:

  1. cuántas páginas necesita cada proceso;
  2. cuántos marcos necesita cada proceso;
  3. si las páginas necesitan estar contiguas;
  4. qué sucede con el Proceso B de 4 KB;
  5. qué tipo de fragmentación puede existir.

39.3 Parte C — Reflexión

Responde:

¿Qué problema de las particiones dinámicas deja de ser crítico cuando utilizamos paginación?

Tip✅ Solución propuesta

39.3.1 First Fit

Huecos iniciales:

8, 5, 12, 7

Proceso A = 6 KB:

2, 5, 12, 7

Proceso B = 4 KB: el primer hueco suficiente es 5 KB.

2, 1, 12, 7

Proceso C = 7 KB: el primer hueco suficiente es 12 KB.

2, 1, 5, 7

39.3.2 Best Fit

Proceso A = 6 KB → utiliza 7 KB:

8, 5, 12, 1

Proceso B = 4 KB → utiliza 5 KB:

8, 1, 12, 1

Proceso C = 7 KB → utiliza 8 KB:

1, 1, 12, 1

39.3.3 Worst Fit

Proceso A = 6 KB → utiliza 12 KB:

8, 5, 6, 7

Proceso B = 4 KB → utiliza 8 KB:

4, 5, 6, 7

Proceso C = 7 KB → utiliza 7 KB:

4, 5, 6, 0

39.3.4 Paginación de 2 KB

  • Proceso A = 6 KB → 3 páginas / 3 marcos.
  • Proceso B = 4 KB → 2 páginas / 2 marcos.
  • Proceso C = 7 KB → necesita 4 páginas / 4 marcos; la última página utiliza solo 1 KB.

Las páginas no necesitan estar en marcos contiguos.

En el Proceso C aparece hasta 1 KB de fragmentación interna en su último marco.

La paginación evita que los huecos libres dispersos impidan por sí solos cargar un proceso, siempre que existan suficientes marcos libres.

40 24. Errores comunes

40.1 “Fragmentación interna y externa son lo mismo”

No.

  • Interna → espacio desperdiciado dentro de una unidad asignada.
  • Externa → memoria libre dispersa entre unidades ocupadas.

40.2 “Best Fit siempre es la mejor estrategia”

El nombre puede engañar. Significa que selecciona el hueco más ajustado, no que produzca necesariamente el mejor comportamiento en todas las situaciones.

40.3 “Las páginas deben quedar juntas en RAM”

No. Precisamente una de las ventajas fundamentales de la paginación es permitir distribución no contigua.

40.4 “Página y marco son sinónimos”

Tienen el mismo tamaño dentro de un esquema paginado, pero representan cosas distintas:

Página → espacio lógico
Marco  → memoria física

40.5 “La paginación elimina toda fragmentación”

No. Evita la fragmentación externa clásica, pero puede existir fragmentación interna.

42 26. Reto final

Un sistema utiliza páginas de 4 KB.

Un proceso necesita 18 KB.

Responde:

  1. ¿Cuántas páginas necesita?
  2. ¿Cuántos marcos debe recibir?
  3. ¿Cuánta memoria física se asignará en total?
  4. ¿Cuánta fragmentación interna tendrá el último marco?
  5. Si la Página 3 está en el Marco 9 y el desplazamiento es 500 bytes, ¿cuál es la dirección física?
  6. ¿Las cinco páginas deben quedar en marcos consecutivos?
Tip✅ Solución propuesta

42.0.1 1. Número de páginas

18 KB ÷ 4 KB = 4.5

Necesitamos 5 páginas.

42.0.2 2. Número de marcos

Cada página necesita un marco, por lo que necesitamos 5 marcos.

42.0.3 3. Memoria física asignada

5 × 4 KB = 20 KB

42.0.4 4. Fragmentación interna

20 KB - 18 KB = 2 KB

La fragmentación interna es 2 KB.

42.0.5 5. Dirección física

Como:

4 KB = 4096 bytes
Marco = 9
Desplazamiento = 500

entonces:

Dirección física = (9 × 4096) + 500
                  = 36864 + 500
                  = 37364

La dirección física es 37364.

42.0.6 6. ¿Deben ser consecutivas?

No. Las páginas pueden almacenarse en marcos físicos no contiguos.
